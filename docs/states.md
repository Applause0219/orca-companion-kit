# 寵物的狀態與打斷規則

寵物的動作越來越多（捉迷藏、蹭蹭、讀文件、提燈……），哪個能蓋過哪個要有個規則。這份文件把現有的動作分成四層，寫下每一層的優先順序、能不能被打斷、能不能打斷自己。要加新動作的時候，先決定它屬於哪一層，再照那一層的規則寫。

程式都在 `src/touches/companion.js`。這份文件只描述它現在怎麼運作，不是另一套機制；兩邊對不上的地方列在最後的「現況和規則不一樣的地方」。

## 兩個開關：`mode` 和 `busy`

打斷全靠這兩個變數，沒有另外的排程器。

- **`mode`：牠人在哪裡、在做哪一類事。** `home`（在家）、`asleep`（睡著）、`flying`（被甩出去或正在飛回家）、`following`（跟著游標）、`visiting`（去敲等你的分頁）、`hiding`（捉迷藏）。只有 `home` 的時候才會自己開始新的動作。
- **`busy`：牠正在演的那一段動作。** 是一個有 `cancel()` 的物件：`act()` 回傳的 WAAPI 動畫，或長動作自己做的「佔位」（`{ cancel, playState: 'running' }`）。`busy` 不是空的，閒置動作就不會開始；誰要搶，就呼叫 `busy?.cancel()` 再把 `busy` 設成 `null`。

另外 `drag`（正被抓著）和 `free()`（在家、沒被抓、沒在散步、視窗看得到）也是常用的條件。

`mode` 一律用 `setMode(新狀態, 原因)` 改，不要直接設值（測試會擋）。抓狀態亂跳的問題時，到設定面板「你和牠」打開「開發：顯示狀態」（`debugState`，預設關）：牠頭上會顯示現在的 `mode`，每次轉換在主控台用 `console.debug` 記一行「舊→新（原因）」（DevTools 要把 Verbose 打開才看得到）。關著的時候不會產生任何元素，也不會記任何東西。

## 四層與優先順序

數字大的可以打斷數字小的，反過來不行。

| 優先 | 層 | 是什麼 | 誰叫它開始 |
| --- | --- | --- | --- |
| 4 | **alert** | agent 分頁的事：有分頁等你允許、做完、失敗 | Orca 分頁的狀態改變 |
| 3 | **reaction** | 你對牠做了什麼、說了什麼 | 點、摸、拖、甩、終端機送出的字、git、游標掃過、離開後回來 |
| 2 | **walk** | 換位置、換 `mode` 的事 | 散步、跟著走、捉迷藏、飛回家 |
| 1 | **idle** | 沒事時自己找事做 | 計時器、牠自己的狀態（心情、時間、游標停著） |

另外有一些**疊加效果**不算任何一層：眨眼、眼睛跟著游標、打字時跟著晃、agent 工作時的呼吸光暈、低落時耳朵垂下、心情的小符號、提燈。它們不碰 `busy`，也不換 `mode`，用 `composite: 'add'` 疊在別的動作上，誰都不打斷誰（唯一的例外：捉迷藏時提燈會先收起來，免得燈光洩漏藏身處）。

## 每一層的規則

### idle（優先 1）

- **開始的條件**：`mode === 'home'`、`!busy`、`!drag`，而且視窗看得到（多數用 `free() && !busy`）。條件不合就這次不做，不排隊。
- **能被打斷**：可以。任何 reaction、alert、walk 都能把它取消。長的 idle 動作要把收拾的函式放進 `busy.cancel`，被取消時道具、迴圈動畫都要拿掉。
- **能打斷自己**：不行。一個 idle 動作演完，下一個才會開始；閒置挑選也不會連續挑同一個。
- **現有的**：閒置動作（`acts` 裡有 `weight` 的：`wiggle`、`lookAround`、`stretch`、`doze`、`hum`……）、睡著（`asleep`）、讀文件、蹭蹭、連按刪除時歪頭、鬧彆扭、被抓包的場景、不安時說的話。

### walk（優先 2）

- **開始的條件**：在家（`home`，跟著走和捉迷藏也接受 `asleep`，會先叫醒）而且沒被抓著。開始時把 `mode` 換掉，或像散步一樣設 `roaming = true` 再放一個佔位的 `busy`。
- **能被打斷**：可以，但只有幾個固定的出口，見下表。每個 `await` 之後都要再檢查 `mode` 還是不是自己設的那個，不是就收手、不要把 `mode` 改回去。
- **能打斷自己**：不行。在 `following` 時再雙擊是「結束跟隨」，在 `hiding` 時點牠是「找到了」，都是結束，不是重來。
- **結束時**：一定要把 `mode` 設回 `home`（或把 `roaming` 設回 `false`），否則 idle 永遠不會再開始。

| 動作 | 狀態 | 怎麼結束 |
| --- | --- | --- |
| 散步 `wander` | `home` + `roaming` | 自己走回家；途中被抓起來、或 `mode` 變了就停在原地 |
| 跟著走 | `following` | 在任何地方按右鍵、或再雙擊牠（不綁 Esc） |
| 捉迷藏 | `hiding` | 點到牠（找到）、時間到（沒找到）、有分頁在等你（alert） |
| 甩出去、飛回家 | `flying` | 落地後自己飛回家，回到 `home` 再做招牌動作 |

### reaction（優先 3）

- **開始的條件**：多數要 `mode === 'home'` 而且沒被抓著；拖動也接受 `asleep`、`visiting`。
- **能被打斷**：可以，被下一個 reaction 或 alert 打斷。
- **能打斷自己**：可以。新的 reaction 會先 `busy?.cancel()` 把上一個收掉（`play(name)` 就是這樣做的）。為了不要一直被打斷，每一種都有自己的冷卻：關鍵字 8 秒、git 5 秒、摸頭 2.5 秒、游標掃過 20 秒。
- **現有的**：點一下（`poke`）、摸頭（`happy`）、拖動和甩、終端機的關鍵字和名字、唱歌、git commit 蓋章、git push 紙飛機、游標掃過嚇一跳、離開後回來的歡迎、每天第一次見面的招呼和紀念日。

### alert（優先 4）

- **開始的條件**：Orca 分頁的 `data-agent-activity-status` 改變（每 3 秒也會補看一次）。
- **能被打斷**：只有你能打斷：點牠就去開那個分頁，把牠拖走就不敲了。分頁不再等你時牠自己回家。
- **能打斷自己**：不行。同時有好幾個分頁在等，牠只去敲畫面上那一個；牠已經在敲門時，在等的分頁換了也不會跟著換（見最後一節）。
- **現有的**：有分頁等你允許時去敲門（`visiting`）、agent 做完轉一圈（`twirl`）、失敗時垂頭（`droop`）。工作中的呼吸光暈是疊加效果，不算這一層。

## 不只靠顏色

色弱的人、或只是瞄一眼的時候，分不出光暈深一點淺一點。所以每個看得到的狀態，除了顏色和明暗，還要有姿勢、位置或一個小符號能認出來。下表逐條列出現在的樣子；「非顏色提示」寫 **待補** 的，就是目前只靠顏色或明暗。新增狀態時也補一行。

| 狀態 | 顏色、明暗 | 非顏色提示 |
| --- | --- | --- |
| 在家 `home` | 平常的亮度 | 待在家的位置，睜著眼 |
| 睡著 `asleep` | 變暗一點 | 閉眼的弧線、往一邊歪、頭上一直冒「z」 |
| 飛 `flying` | 無 | 位置在動；甩出去時會轉 |
| 跟著走 `following` | 身後的小光點 | 一路貼著游標移動 |
| 敲門 `visiting` | 無 | 停在那個分頁下面左右敲，冒「!」 |
| 捉迷藏 `hiding` | 無 | 躲在邊緣只露一點，偶爾冒「嘻」 |
| agent 工作中 | 身後光暈一明一暗 | **待補**：引擎只有光暈；寵物設 `glow: false` 時什麼都看不到。Puff 示範一個做法：工作中閒著時偶爾抬頭、頭上冒「⚙」（`examples/touches/puff.js` 的 `busyToo`） |
| agent 做完 | 星星 | 轉一圈（牠在忙就跳過，見最後一節） |
| agent 失敗 | 變暗、光暈熄掉 | 往下沉、歪倒、耳朵壓平，冒「!?」；減少動態效果時只剩變暗和「!?」 |
| 低落 | 變暗一點 | 耳朵垂下。**待補**：減少動態效果時耳朵不動，只剩變暗 |
| 鬧彆扭 | 變暗 | 躲到下面的角落、身體歪向牆邊、冒「……」、說一句話 |
| 讀文件 | 無 | 戴上眼鏡 |
| 心情符號 | 各有顏色 | 每種字形都不同：♡、?、…、z、!?、! |
| 連擊光暈 | 光越來越亮 | 每 50 下轉一圈；打字特效開著時右上角有連擊數字 |
| 提燈 | 燈光 | 身邊多一盞燈的形狀 |

## 「試試看」不照這個表

設定面板的「試試看」會先把牠整個清乾淨（結束跟隨、捉迷藏、敲門、讀文件、抓包場景，叫醒，取消 `busy`），再演那一個。這是給你預覽用的，不算任何一層；新的預覽也照這個做法，不要繞過它。

## 加新動作時

1. **先選層。** 牠自己會做的是 idle，會換位置的是 walk，回應你的是 reaction，跟 agent 分頁有關的是 alert。拿不定就選低的那層：低優先的動作晚一點演沒關係，高優先的動作打斷錯了會很吵。
2. **照那層的條件開始。** idle 檢查 `free() && !busy`；reaction 先 `busy?.cancel()` 再 `busy = null`；walk 換 `mode`；alert 不要搶 walk 的 `mode`，除非像捉迷藏這樣有明確的收尾函式（`endSeek()`）。
3. **超過一個動畫長度的動作要佔住 `busy`。** 做一個 `hold = { cancel: 收拾函式, playState: 'running' }` 放進 `busy`，結束時只在 `busy === hold` 的時候才清掉，免得把別人的動作清掉。
4. **每個 `await` 和計時器回來都要再檢查。** `stopped`、`mode`、`drag`，以及自己的 hold 還在不在。
5. **寵物檔裡的動作**（`acts`、`reactions`）不用管這些：`api.act()` 會自己設好 `busy`；`api.busy`、`api.mode` 可以讀，決定要不要做。見 [companion-api.md](companion-api.md#動作-acts)。
6. **補一行到上面的「現有的」**，有例外就寫進下一節。

## 現況和規則不一樣的地方

這些是寫這份文件時在程式裡看到、和上面的層次對不上的行為。之後改引擎的時候可以順手對齊；在那之前，它們就是現在的行為。

- **敲門會等 idle 演完。** alert 理應最優先，但去敲門的條件是 `mode === 'home' && !busy && !drag`，所以牠在讀文件（最長 45 秒）、唱歌、鬧彆扭時不會立刻去，要等下一次檢查（最多 3 秒一次）剛好閒下來。牠在跟著走時也不會去敲。
- **敲門時不會換分頁。** 牠在 `visiting` 時，`visit()` 只處理「沒有分頁在等」這一種（回家）。原本那個分頁不等了、換另一個在等，牠會留在原地，等所有分頁都不再等你才回家。
- **做完的轉圈遇到忙就跳過。** `twirl()` 看到 `busy` 就直接 return，不排隊；失敗的垂頭則不管忙不忙都會演。
- **任何 reaction 都會結束鬧彆扭。** 鬧彆扭把 `endSulk` 放在 `busy.cancel`，所以打一個關鍵字也會讓牠不再彆扭（只是不算「被哄好了」）；只有摸三下才算和好。
- **被抓包是 reaction 的時機、idle 的條件。** 它在你回到視窗時才觸發，卻用 idle 的條件（`free() && !busy`），所以回來時牠在忙就改演普通的歡迎。
- **摸頭、說話不佔 `busy`。** `happy()` 和對話框只疊加動畫，不取消也不佔住正在演的動作。
